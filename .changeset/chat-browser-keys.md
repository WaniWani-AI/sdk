"@waniwani/chat": minor
---

The chat keeps less in the browser, under fixed names, and nothing lives longer than 13 months. It uses one visitor ID: `memoryUserId` in a request's `extra` (read by MCP servers as `_meta["waniwani/extra"].memoryUserId`) carries the visitor ID's value, so a server that keyed data on the old value sees a new ID once. The browser keys are `waniwani-visitor-id` (localStorage, 13 months from creation), `waniwani-chat-session`, `waniwani-agent-session` and `waniwani-config` (sessionStorage, deleted when the tab closes), and the IndexedDB database `waniwani-threads`, which the chat creates only when thread history is on and from which it deletes threads 13 months old. A saved conversation reopens after a reload in the same tab, and a new tab starts a new one. On load the chat deletes the keys older releases wrote (`waniwani-memory-user-id`, `waniwani:eve-conversation:*`, `waniwani:config:*`, `waniwani:webmcp:session` and the `waniwani-memory` database); local thread history saved by older releases is not carried over.
